Controller v3 · implementation spec

Archived draft: PPO recovery with an MPC fallback

Keep the frozen v2 result immutable. Run a small lexicographic reward-and-training sweep on development data before building a new controller. Escalate to a safety layer and causal MPC only if repaired PPO cannot complete work and beat spatial-only control.

Recommended first move: successive-halving PPO reward/credit sweep; MPC is the fallback

01The problem to solve

Before · frozen v2 joint PPO
  1. One flat 3N Gaussian action jointly changes service routing, batch release, and batch placement.
  2. Service receives priority, so a poor routing action can create transient backlog even when fleet capacity exists.
  3. Batch safety is encouraged through penalties, not guaranteed by the action parameterization.
  4. γ=1, but default gae_lambda=0.95 greatly attenuates credit over 40–270 minute deadlines.
  5. Result: only 9/40 batch seeds meet completion; one seed incurs $2.289M backlog cost; joint headline fails.
After · controller v3
  1. Expose episode progress and deadline buckets so terminal flushing and urgency are Markov.
  2. Separate service-backlog and batch-completion weights instead of coupling both to one $1,000 floor.
  3. Sweep GAE λ, idle-cost subtraction, urgency potential shaping, and penalties with safety-first selection.
  4. Train only temporal heads with spatial routing frozen as the cheapest interference diagnostic.
  5. Build a safety layer/MPC only if no PPO variant produces exact completion and positive development gains.

What already works

Spatial PPO is viable

Global spatial succeeds in both folds with complete service. The algorithm is not universally broken; joint credit and feasibility are.

Root failure

Three coupled controls interfere

The catastrophic seed comes from transient service backlog, not merely the tiny terminal batch pool. Routing and temporal heads damage one another.

Available leverage

The system is convex underneath

The existing Clarabel QP already models service, queue, deadlines, capacity, and the primary objective. It can be refactored into causal MPC.

Critical hidden-state finding: completion-guarded batch observations include hour-of-day but not episode progress. The policy is penalized for a terminal pool yet cannot know the month is ending. Add normalized steps-remaining before interpreting another reward sweep.
Methodological boundary: v3 is a post-hoc algorithmic follow-up. The frozen v2 negative result remains the confirmatory result. With no untouched Google month/cells left, v3 cannot be presented as a fresh confirmatory test without a new workload trace.

09Test requirements

Unit
  • Deadline buckets sum exactly to pool demand.
  • Idle-cost subtraction changes every policy return by the same constant.
  • Capped service allocation preserves total service and site capacity.
  • Mandatory EDF completion cannot be scaled below its floor.
  • Terminal flush reaches zero pool on feasible traces.
Integration
  • 240-step safe-controller run matches a small convex reference.
  • MPC uses no realized future data and reproduces stored teacher actions.
  • Random raw actions remain service/batch feasible after projection.
  • BC checkpoint reproduces teacher mean action within tolerance.
  • Executed-action accounting drives reward and evaluation consistently.
Campaign
  • 3-seed cheap gate before any 10-seed campaign.
  • No service backlog, expiry, or terminal pool in every seed.
  • Paired joint-vs-spatial statistics pre-registered.
  • Demand charge and ramp regressions reported independently.
  • Source/data/model/teacher hashes frozen and verified.

11Implementation notes and warnings

Backward compatibility. Do not mutate or overwrite v2 models, protocol, summary, or thesis claims. V3 gets new environment flags, model roots, output roots, and protocol IDs.
Hard warning. A safety layer cannot guarantee an infeasible workload. Every guarantee must be conditioned on a checked fleet-capacity/deadline schedulability invariant.
Reward correctness. Zero-load cost is action-independent and safe to subtract. Recompute the variable-cost scale and economic penalty floor afterward; evaluation always uses original dollars.
MPC teacher validity. Distillation is valid only when the student receives the same causal forecast information. Never train on teacher actions generated with realized test futures.
Performance. Replan MPC every 12 steps with a 72-step horizon and warm-start Clarabel. Safety decoding remains five-minute and should be sub-millisecond for N=4.
Algorithm pivot rule. RecurrentPPO and SAC do not repair an unsafe action space. If safe PPO cannot capture ≥50% of causal MPC savings, make MPC the primary controller instead of running another broad horse race.
Why not start with SAC?
The v2 failure is dominated by joint-head interference, transient service backlog, and completion feasibility. SAC may improve sample efficiency, but it inherits the same unsafe 3N action semantics and adds a discounted off-policy objective that is awkward with the finite-horizon γ=1 accounting. Use it only after the safety kernel and teacher baseline exist.
Why build MPC if the thesis is about RL?
The causal MPC establishes what a feasible controller can achieve with the same information, supplies safe teacher actions, and provides a scientifically defensible pivot. If PPO learns the MPC policy more cheaply at runtime, RL adds value. If it does not, the honest controller is MPC and PPO remains the important negative result.
